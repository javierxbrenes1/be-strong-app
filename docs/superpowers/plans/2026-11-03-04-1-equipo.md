# Pantalla Equipo: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reescribir `/equipment` con el diseño Iron y validar el patrón de feature + sheets que usarán las demás pantallas.

**Architecture:** La feature vive en `src/client/features/equipment/` con documentos tipados (codegen), schemas zod y componentes. Crear y editar se hace en `AppSheet`, y borrar con `ConfirmDialog`. Al final se borra `src/client/pages/equipment/`.

**Tech Stack:** React 18, MUI (tema Iron), Apollo Client 3 + codegen, react-hook-form + zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-04-pantallas-design.md` §"Reglas comunes" y §4.1 · base en `docs/superpowers/plans/2026-11-03-03-base-frontend.md`.

## Global Constraints

- Rama `redesign/04-1-equipo` desde `master` con el plan 3 integrado.
- Commits sin `Co-Authored-By` ni atribución a IA.
- Usar los componentes del plan 3 con sus firmas: `AppSheet`, `ConfirmDialog`, `FormTextField`, `FormNumberField`, `zNumber`, `EmptyState`, `PageHeader` y `KpiCard` si aplica.
- Nada de edición inline ni `contentEditable`.
- Las reglas de datos del plan 3: `graphql()` tipado, sin `onCompleted`/`onError` en queries, y `refetchQueries` con el documento.
- Sin emojis ni colores hex. Textos en español correcto. Cada ícono-botón con `aria-label`.
- 390, 768 y 1440px sin scroll horizontal.
- Ejecutar `npm run codegen` (con el servidor arriba) cada vez que cambien los documentos.

## Review Focus

- Total de equipo en blanco, negativo o decimal (`2.5`): error de validación, no se envía. Test en Task 1.
- Categoría con nombre que solo tiene espacios: "Requerido". Test en Task 1.
- Al editar una categoría, quitar una fila de equipo existente: ese equipo se borra en el servidor; las filas nuevas se crean y las editadas se actualizan. Verificación en Task 3.
- Borrar la última categoría muestra el estado vacío, no una página en blanco. Verificación en Task 4.
- Doble clic en "Guardar": una sola mutación (botón con `loading`/`disabled` mientras corre). Verificación en Task 3.

### Task 3: Sheet de categoría (crear, editar y renombrar)

**Files:**
- Create: `src/client/features/equipment/CategorySheet.tsx`
- Create: `src/client/features/equipment/saveCategory.ts` y `saveCategory.test.ts`

**Interfaces:**
- Consumes: `categorySchema`, los documentos de la Task 1, `AppSheet`, `FormTextField` y `FormNumberField`.
- Produces:
  - `<CategorySheet open: boolean; category?: { uuid: string; name: string; equipment: Equipment[] }; onClose: () => void />`. Sin `category` crea; con `category` edita.
  - `planCategoryChanges(original: Equipment[], edited: EquipmentForm[]): { create: EquipmentForm[]; update: EquipmentForm[]; remove: string[] }`, función pura. `update` solo incluye las filas con `uuid` cuyo contenido cambió.
- Comportamiento:
  - Título "Nueva categoría" o "Editar categoría".
  - Campos: Nombre y la lista de equipos (`useFieldArray`). Cada fila tiene Descripción, Marca, Total y un botón quitar (`aria-label="Quitar {descripción}"`). Debajo, "+ Agregar equipo".
  - Al crear: `addEquipmentCategory(name, equipment)`.
  - Al editar: `updateEquipmentCategoryName` si el nombre cambió, `upsertEquipment` para crear y actualizar, y `deleteEquipment` para quitar, todo con `Promise.all`. Al final, `refetchQueries: [EquipmentCategoriesDocument]`, toast "Categoría guardada" y cierre.
  - `dirty = formState.isDirty`. El botón primario usa `loading` mientras guarda.
