# Pantalla Miembros: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reemplazar el grid de tarjetas de `/members` por una lista densa con estado, última asistencia y peso actual, y crear la sheet "Miembro" (alta y edición) que también usará el detalle.

**Architecture:** El servidor agrega dos campos calculados a `Member`, resueltos en lote con DataLoader (sin N+1). El estado "En riesgo" se calcula con una función pura compartida en `src/common`. El cliente vive en `features/members/`.

**Tech Stack:** Apollo Server 4 + Prisma, `dataloader`, React 18 + MUI (Iron), Apollo Client + codegen, react-hook-form + zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-04-pantallas-design.md` §4.3 (bugs B4 y B5).

## Global Constraints

- Rama `redesign/04-3-miembros` desde `master` con el plan 4.2 integrado.
- Commits sin `Co-Authored-By` ni atribución a IA.
- **"En riesgo"** = miembro activo **sin asistencia en más de 14 días** (`RISK_DAYS = 14`, confirmado por el dueño). Un miembro activo que **nunca** asistió también cuenta como en riesgo.
- **"Sin medirse"** = más de 90 días (`UNMEASURED_DAYS = 90`). Lo usa el plan 4.6; aquí solo se declara la constante.
- Categorías: `A1`–`A7` (`MemberCategories` en `src/client/types.ts`). Géneros: `male` = Masculino, `female` = Femenino, `other` = Otro.
- Teléfono: máximo 10 caracteres (`varchar(10)`). Correo: formato válido. Estatura en metros, decimal entre 0.5 y 2.5. Nombre: requerido, máximo 100.
- `birthDate` es un `LocalDate` (plan 2). Avatares siempre con `MemberAvatar` (iniciales); **no** usar `member.avatar`.
- No usar el string `'homeQueries'` en `refetchQueries` (B5).
- Componentes y reglas de datos del plan 3. Sin colores hex ni emojis.

## Review Focus

- Miembro activo que nunca asistió: estado "En riesgo" y "Última asistencia" = "Sin asistencias". Test en Task 1.
- Asistencia exactamente hace 14 días: **no** está en riesgo; hace 15 sí. Test en Task 1.
- Teléfono de 11 dígitos o correo `carlos@`: error en el campo y no se envía. Test en Task 3.
- Estatura escrita con coma (`1,78`): se acepta como 1.78. Test en Task 3.
- Búsqueda de 1 carácter con escritura rápida: una sola request tras 300 ms de pausa. Verificación en Task 2.

- Create: `src/server/apollo/loaders/memberSummaryLoader.ts`
- Modify: `src/server/apollo/context.ts` (agregar `loaders: { memberSummary: DataLoader<string, MemberSummary> }`, una instancia por request)
- Modify: `src/server/apollo/typeDefs/memberSchema.ts` (`Member.lastAttendanceDate: LocalDate`, `Member.currentWeight: Float`)
- Modify: `src/server/apollo/resolvers/member/index.ts` (field resolvers de `Member`)

**Interfaces:**
- Produces:
  - `type MemberStatus = 'active' | 'inactive' | 'risk'`
  - `memberStatus(isActive: boolean, lastAttendance: LocalDate | null, today: LocalDate): MemberStatus`
  - `type MemberSummary = { lastAttendanceDate: LocalDate | null; currentWeight: number | null }`
  - El loader resuelve un lote de `code[]` con **2 queries**:
    1. `SELECT l."memberCode", max(g."classDate")::text FROM app."memberAttendanceLog" l JOIN app."gymClass" g ON g.id = l."gymClassId" WHERE l."memberCode" = ANY($1) GROUP BY 1`
    2. `SELECT DISTINCT ON ("memberCode") "memberCode", weight FROM app."memberMeasures" WHERE "memberCode" = ANY($1) ORDER BY "memberCode", date DESC`
  - Los field resolvers `Member.lastAttendanceDate` y `Member.currentWeight` usan `ctx.loaders.memberSummary.load(parent.code)`. Las queries que listan miembros deben pedir `code`.
