# Pantalla Clases: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rediseñar `/classes` con navegación por día, cards de clase con horarios, una sheet única "Pasar lista" y una sheet "Nueva clase" con autocompletado de tipos.

**Architecture:** `features/classes/` con documentos tipados. "Pasar lista" calcula la diferencia entre los asistentes iniciales y los seleccionados con una función pura, y llama a las mutations existentes. Se agrega una query `@auth` para los tipos de clase usados. El plan 4.6 reutiliza `AttendanceSheet`.

**Tech Stack:** React 18 + MUI (Iron), Apollo Client + codegen, react-hook-form + zod, `@uiw/react-md-editor` (ya instalado), Apollo Server + Prisma, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-04-pantallas-design.md` §4.4.

## Global Constraints

- Rama `redesign/04-4-clases` desde `master` con el plan 4.3 integrado.
- Commits sin `Co-Authored-By` ni atribución a IA.
- El día seleccionado es un `LocalDate`; "hoy" = `todayLocalDate()`. Los horarios son `LocalTime` mostrados con `formatLocalTime`.
- **"Pasar lista": sin preselección por plan semanal** (decisión del dueño). Vienen marcados solo los asistentes ya registrados en ese horario. Opcional: la etiqueta "plan" junto a los miembros cuyo plan incluye ese día de la semana, solo informativa.
- La lista de "Pasar lista" muestra solo miembros **activos**, ordenados por nombre.
- Nueva clase: tipo requerido (máx. 50), duración entera > 0 (opcional), al menos un horario, descripción Markdown opcional. La fecha es el día seleccionado.
- Componentes y reglas de datos del plan 3. Sin colores hex ni emojis.

## Review Focus

- Guardar "Pasar lista" sin cambios: no llama a ninguna mutation y cierra con el toast "Sin cambios". Test en Task 2.
- Desmarcar a alguien ya registrado y marcar a otro nuevo: una `remove` con el primero y una `add` con el segundo. Test en Task 2.
- Navegar a un día pasado y crear una clase: la clase queda en **ese** día, no en hoy. Verificación en Task 3.
- Descripción Markdown larga: la card la colapsa (máx. ~6 líneas con "Ver más"). Verificación en Task 1.
- Clase sin asistentes en un horario: el horario muestra "0 asistentes" y el botón "Pasar lista". Verificación en Task 1.
