# Inicio "Hoy": plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convertir `/` en un tablero del día: KPIs, clases de hoy con "Pasar lista", recordatorios (cumpleaños, en riesgo, sin medirse) y asistencia de los últimos 7 días.

**Architecture:** Una query de servidor `getHomeSummary(today)` (`@auth`) que agrega todo en pocas consultas SQL. El cliente vive en `features/home/` y reutiliza `AttendanceSheet` (plan 4.4), `KpiCard` y `MemberAvatar`.

**Tech Stack:** Apollo Server + Prisma `$queryRaw`, React 18 + MUI (Iron), Apollo Client + codegen, chart.js, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-04-pantallas-design.md` §4.6 · wireframe en `docs/INSPIRACION.md` §5 y la sección "Inicio" de `docs/preview/estilos.html`.

## Global Constraints

- Rama `redesign/04-6-inicio` desde `master` con el plan 4.5 integrado.
- Commits sin `Co-Authored-By` ni atribución a IA.
- Umbrales confirmados por el dueño, desde `src/common/thresholds.ts`: **en riesgo** = activo con más de `RISK_DAYS` (14) días sin asistir (o que nunca asistió); **sin medirse** = activo sin medición en más de `UNMEASURED_DAYS` (**90**) días (o que nunca se midió).
- La semana va de lunes a domingo, en `GYM_TIMEZONE`. "Hoy" = `todayLocalDate()`, que envía el cliente.
- **Decisión del planificador:** los recordatorios muestran hasta 5 nombres por grupo (cada uno enlaza a `/members/:code`) y "y N más" expande la lista completa dentro de la misma card. No se agregan filtros nuevos a la lista de Miembros.
- Componentes y reglas de datos del plan 3. Sin colores hex ni emojis.

## Review Focus

- Lunes temprano: "asistencias esta semana" cuenta solo desde el lunes de hoy, y la semana anterior va de lunes a domingo completa. Test en Task 1.
- Sin clases hoy: la card "Clases de hoy" muestra un estado vacío con "Ir a Clases", no una card vacía. Verificación en Task 2.
- Muchos miembros en riesgo (más de 5): se ven 5 más "y N más", y al expandir se ven todos. Verificación en Task 2.
- Cumpleaños de un miembro **inactivo**: no aparece (comportamiento actual). Verificación en Task 1.
- Pasar lista desde Inicio actualiza también el conteo de la card sin recargar. Verificación en Task 2.

### Task 1: Query `getHomeSummary`

**Files:**
- Create: `src/common/weekBounds.ts` y `weekBounds.test.ts`
- Create: `src/server/apollo/typeDefs/homeSchema.ts` (registrado en `typeDefs/index.ts`)
- Create: `src/server/apollo/resolvers/home/getHomeSummary.ts` e `index.ts` (registrar en `resolvers/index.ts`)

**Interfaces:**
- Produces:
  - `weekBounds(today: LocalDate): { thisWeek: { from: LocalDate; to: LocalDate }; lastWeek: { from: LocalDate; to: LocalDate } }`, de lunes a domingo, con `to` inclusivo.
  - SDL:
```graphql
type DayCount { date: LocalDate! count: Int! }
type HomeMemberRef { code: String! name: String! }
type HomeSummary {
  activeMembers: Int!
  newMembersThisMonth: Int!
  attendancesThisWeek: Int!
  attendancesLastWeek: Int!
  last7Days: [DayCount!]!            # 7 elementos, de hoy-6 a hoy, con count 0 si no hubo
  birthdays: [HomeMemberRef!]!
  atRisk: [HomeMemberRef!]!
  unmeasured: [HomeMemberRef!]!
}
extend type Query { getHomeSummary(today: LocalDate!): HomeSummary! @auth }
```
  - Las asistencias se cuentan por `memberAttendanceLog` unido a `gymClass.classDate`. `newMembersThisMonth` usa `member.createAt` (instante) en el mes actual de `GYM_TIMEZONE`. Cada lista se resuelve con una sola query SQL, ordenada por nombre.

expect(weekBounds('2026-11-02').thisWeek.from).toBe('2026-11-02'); // lunes

- Produces: `<HomePage />` con:

  - `TodayClassesCard`: una fila por clase y horario de hoy con la hora (`metric`), el tipo, "N asistentes" y el botón "Pasar lista" (abre `AttendanceSheet`). Si no hay clases, `EmptyState` "No hay clases hoy" con el enlace "Ir a Clases".

  - `Last7DaysChart`: barras con colores de `useChartColors()`, el día de hoy resaltado y el eje X con la inicial del día (L, M, M, J, V, S, D).
  - Layout: en lg, KPIs arriba y luego dos columnas (clases + gráfico | recordatorios); en xs, todo apilado.
  - Después de "Pasar lista", `refetchQueries: [GymClassesByDayDocument, HomeSummaryDocument]`.
